# MSP Phase 0 Implementation Plan — Contract, Conformance, Example Model, Router Stub, Traffic Generator

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver MSP-SPEC-001 §11 Phase 0: contract proto, manifest JSON Schema, conformance CLI (`msp-conform verify <image>`), Python base image + SDK, one example model, a Router stub, and a synthetic traffic generator — with C1–C7 passing on the example model, negative cases caught, and predict round-trips working against both stub and example model.

**Architecture:** Two language islands. `contract/` holds the frozen artifacts (proto, manifest schema, Python SDK + base image, example model). `msp/` is one Go module with three binaries (`msp-conform`, `router-stub`, `msp-traffic`) sharing internal packages for envelope client, golden-sample handling, and manifest parsing — the C3/C5 code reuse the spec requires. Conformance runs models as local docker containers: the model gets `--network none` (zero egress, the local analog of the spec's no-egress NetworkPolicy) and a probe container joins the model's network namespace (`--network container:<id>`) to reach `127.0.0.1:8080`. This also sidesteps macOS's inability to reach container IPs from the host.

**Tech Stack:** Go 1.22+ (google.golang.org/grpc, google.golang.org/protobuf, santhosh-tekuri/jsonschema/v5, gopkg.in/yaml.v3), Python 3.12 (grpcio, protobuf, PyYAML, pytest), Java 17 + Maven (contract bindings for MYSVC only, codegen at build), protoc, Docker. Layout authority: `docs/SCAFFOLDING.md`.

**Spec:** `MSP-SPEC-001-model-serving-platform.md` §4 (contract), §11 Phase 0 (scope + acceptance). Glossary: `CONTEXT.md`.

## Stand-ins and SPEC-GAPs (decided here, recorded in issue #7)

- **STAND-IN (Q7/C7):** platform resource ceiling = `cpu ≤ 8, memory ≤ 16Gi, nvidia.com/gpu ≤ 1`, baked as defaults in `msp/internal/conformance/limits.go`, overridable via `--limits <yaml>`. Swap when Q7 closes.
- **SPEC-GAP (model_digest):** §4.1 says the model reads its own image digest "from manifest at startup", but the digest can't be inside the image it digests. Stand-in: SDK reads env `MSP_MODEL_DIGEST` (platform injects at deploy time), else returns `""`. Conformance does not require a non-empty digest. File as a decision ticket on map #1.
- **Scope note:** acceptance item "MYSVC completes a predict round-trip via the Router stub" is fulfilled here by `msp-traffic` acting as the caller stand-in; the real MYSVC integration lands in MYSVC Phase C.
- **YAGNI:** `comparisonPolicy: top-k:<k>` and `inputSchema.type: jsonschema` are accepted by the manifest schema (contract allows them) but conformance rejects them with an explicit "not implemented in reference build" error. No model uses them yet.

**Interfaces:**
- Produces (frozen, spec §4.5):

```python
class BaseModel:
    def load(self) -> None: ...
    def predict(self, payload: bytes) -> bytes: ...

def serve(model: BaseModel, manifest_path: str = "/opt/msp/model-manifest.yaml", port: int = 8080) -> None
```

- Behavior: `serve()` loads manifest, loads input descriptor set (`google.protobuf.descriptor_pb2.FileDescriptorSet` → `descriptor_pool` → message class), calls `model.load()`, then serves `msp.serving.v1.ModelService`. Per request: parse payload with the input message class (`ParseFromString`; any parse exception → reject) → on failure return `Status: INVALID_INPUT` without calling `predict` (spec §4.3-5) (`# ponytail: parse-failure rejection only; unknown-field strictness needs UnknownFields() walk, add if schema drift alerting demands it`); on success call `predict`, fill `model_name`/`model_version` from manifest, `model_digest` from env `MSP_MODEL_DIGEST` (SPEC-GAP stand-in), `inference_ms` measured, `Status: OK`. `predict` raising → `INTERNAL_ERROR`. **Startup order:** `server.start()` first (non-blocking; gRPC serves from its thread pool), then `model.load()` on the main thread, then flip the ready flag and `wait_for_termination()`. While not ready: `Health` → `ready=false`, `Predict` → `INTERNAL_ERROR` with detail "model loading".

```python
import msp, yaml
from msp.example.v1 import defect_pb2

class DefectCls(msp.BaseModel):
    def load(self):
        with open("/opt/msp/config/params.yaml") as f:
            self.threshold = yaml.safe_load(f)["threshold"]

    def predict(self, payload: bytes) -> bytes:
        inp = defect_pb2.DefectInput.FromString(payload)
        score = sum(inp.features) / (len(inp.features) or 1)
        out = defect_pb2.DefectOutput(
            label="defect" if score > self.threshold else "ok",
            score=round(score, 6))
        return out.SerializeToString()

if __name__ == "__main__":
    msp.serve(DefectCls())
```

**Interfaces:**
- Consumes: `manifest.Load`, `envelope.*`.
- Produces: `msp-conform verify <image> [--limits f.yaml] [--json] [--keep]` → runs C1–C7, prints per-check PASS/FAIL + reasons, exit 0 only if all pass. Hidden `msp-conform probe --manifest <path> --golden-dir <path> --target 127.0.0.1:8080 --startup-seconds N --json` runs C2(wait-ready)+C3+C4+C5+C6 from inside the model's netns and prints a `Report` JSON.

```go
type CheckResult struct{ ID, Name string; Pass bool; Detail string }
type Report struct{ Image string; Checks []CheckResult; Pass bool }
```

**Orchestration (`verify`, host side):**
1. `docker create <image>` → `docker cp` out `/opt/msp/model-manifest.yaml`, `/opt/msp/golden/`, declared descriptor files → `docker rm`.
